A design handoff is much easier to review when the file, the change, and the implementation view stay together.

We are building DESIGN:OS Studio 0.7.6 around that practical result. I opened a local design file, asked an agent for one bounded change, inspected the canvas, and checked the implementation view before treating the work as ready to share.

What that gave me:
• Open a real .fig file locally → keep the working source on the machine
• Ask an existing CLI agent for a change → review the result before accepting it
• Keep or revert the turn → avoid losing the previous decision
• Open Dev Mode → give engineering a concrete starting point
• Capture a GPU frame and compare it → check the screen instead of trusting a description
• Export a .fig archive → leave a handoff artifact the next person can open

From “AI makes a screen” to “a design task ends with a reviewable file and handoff.”

Mình và team đang build ra DESIGN:OS Studio để người dùng nhận file thiết kế, sửa trên máy và giao lại bản có thể làm tiếp.

**DESIGN:OS Studio 0.7.6 — từ file mở được sang một lần bàn giao dùng được.**

Mình thử một việc thật: mở file .fig local, nhờ agent dựng phần đầu, tự rà canvas rồi mở phần code để chuẩn bị handoff.

• Nhận file .fig trên máy → mở và lưu lại trong cùng workflow
• Giao agent một thay đổi nhỏ → thấy kết quả trên canvas trước khi quyết định
• Giữ hoặc hoàn tác lượt sửa → không phải làm lại từ đầu khi thử sai
• Chọn layer trong Dev Mode → có điểm bắt đầu cho React, Tailwind, CSS hoặc SwiftUI
• Chụp GPU frame → so lại màn hình thay vì chỉ đọc mô tả
• Export file .fig → gửi cho người tiếp theo một artifact rõ ràng

Từ “AI dựng xong một màn hình” sang “người dùng làm ra file, quyết định và handoff kiểm tra được”.

Mình và team đang build ra DESIGN:OS Studio để người dùng làm xong một màn hình rồi kiểm tra được nó trước khi gửi cho team.

**DESIGN:OS Studio 0.7.6 — làm trên file thật, xem lại từng bước.**

Mình nghĩ bài toán trong group không phải thêm một ô chat, mà là làm sao agent giúp được việc mà người thiết kế vẫn nhìn thấy và quyết định được.

• Mở một file local → bắt đầu từ artifact thật thay vì ảnh minh họa
• Giao một yêu cầu cụ thể → nhận phần bố cục đầu tiên để sửa tiếp
• Xem thay đổi trên canvas → phát hiện chỗ chưa đúng trước khi handoff
• Dùng Keep hoặc Revert → giữ quyền quyết định ở người làm
• Mở Dev Mode → chuyển một layer thành điểm bắt đầu cho code
• Chạy screenshot diff → có bằng chứng trực quan cho lần kiểm tra

Từ “agent tạo UI rồi thôi” sang “agent làm việc trong workflow có state, review và kiểm tra”.
